# 문제은행 파일 규격 (data/*.js)

각 파일은 아래 형태의 JS. `<script src>`로 로드되므로 fetch 불필요.

```js
window.QUIZ_DATA = window.QUIZ_DATA || {};
window.QUIZ_DATA["s1_tax"] = {
  id: "s1_tax",              // 파일명과 동일
  subject: 1,                // 1 | 2 | 3 | 0(2026 개정사항)
  title: "세제 및 절세전략",  // 영역명
  examCount: 7,              // 실제 시험 문항수
  questions: [
    {
      id: "s1_tax_001",      // 영역id_3자리
      type: "ox",            // "ox" | "mc"
      q: "주권으로 대물변제를 한 경우 증권거래세가 부과된다.",
      answer: true,          // ox: true/false
      explain: "증권거래세는 주권의 유상양도에 부과된다. 대물변제는 채무 소멸이라는 대가가 있는 유상양도이므로 과세대상이다. 반면 상속·증여 같은 무상이전, 채권의 양도, 외국거래소 상장 주권의 양도에는 부과되지 않는다.",
      practice: "실무에서 증권거래세는 매도 체결 시 증권사가 원천징수해 투자자는 따로 신고하지 않는다. 장외에서 주식을 넘길 때는 양도인이 직접 신고·납부해야 해서 비상장주식 거래 상담에서 자주 빠뜨리는 항목이다.",   // 실무 맥락 (선택이지만 모든 문제에 넣는 것을 원칙으로)
      ref: "세제 6. 증권거래세"   // 참고 단원명(화면에 "참고 단원"으로 표시)
    },
    {
      id: "s1_tax_002",
      type: "mc",
      q: "다음 중 국세이면서 간접세에 해당하는 것은?",
      choices: ["소득세", "증권거래세", "취득세", "교육세"],
      answer: 1,             // 0-based index
      explain: "증권거래세는 국세 중 간접세다.\n· 소득세 → 국세 직접세\n· 교육세 → 국세 목적세\n· 취득세 → 지방세(도세·보통세)",
      memo: ["국세 간접세: 부가가치세·주세·인지세·증권거래세·개별소비세"],   // 암기 박스 (선택)
      ref: "세제 1. 국세와 지방세",
      choiceNotes: [         // 보기별 해설. choices와 같은 순서(원래 인덱스)
        {term: "소득세는 개인의 소득에 매기는 국세 직접세다.", theory: "이 보기는 직접세라 정답이 아니다. ...", practice: "..."},
        // ... 4개
      ]
    }
  ]
};
```

규칙
- 반드시 유효한 JS. 작성 후 `node -e "require('vm')..."` 또는 `node --check`로 문법 검사.
- 문자열 안의 따옴표는 이스케이프하거나 작은따옴표 사용. 줄바꿈은 `\n`.
- 해설 텍스트(`explain`, `practice`, `choiceNotes`의 각 칸)에서 `· `로 시작하는 줄은 글머리표 목록으로 표시된다. 줄바꿈은 `\n`. 긴 나열은 문장 대신 글머리표로 쓴다.
- `explain`은 정답의 핵심 이유 1~2문장 + 필요하면 `· ` 글머리표 2~4개. 보기마다 "→ 맞다/틀리다"로 훑는 줄은 쓰지 않는다(보기별 해설과 중복). `암기:` 줄도 쓰지 않는다.
- `memo`(선택, 문자열 배열)는 "암기" 박스에 글머리표로 표시된다. 0~4개, 항목마다 사실 하나를 짧게: `A → B`, `A: B·C·D` 꼴. 예: `"시·군세 보통세: 주민세·재산세·자동차세·지방소득세·담배소비세"`.
- `practice`는 "실무에서는" 칸에 표시된다. 2~3개 짧은 문장 또는 글머리표. 이 개념이 실무에서 등장하는 장면, 규칙의 취지, 흔한 착각을 쓴다. explain·memo 반복 금지, 원문에 없는 수치·날짜·조문 번호 창작 금지.
- `case`(선택)는 "실무에서는" 칸 아래 사례 박스로 표시된다. `{type:"real", year, title, text, src, srcName}`은 실제 사례로, 웹에서 확인한 공개 사실만 쓰고 확인한 페이지 URL(https)을 src에 단다. 임직원 실명은 쓰지 않는다. `{type:"example", title, text}`는 "가상 사례" 표시가 붙고 A증권·B운용처럼 가상의 이름을 쓴다. 사례가 도움이 안 되면 생략한다.
- `concept`(개념 칸)는 해설 맨 앞에 표시된다. 정의, 구조, 공식 전체(`$ `로 시작하는 줄은 공식 상자)와 모든 변수 풀이(`· 기호 = 뜻`)를 쓴다.
- `vars`(기호 사전, `{"F": "선물 이론가격", ...}`)는 공식이 있는 문제에 반드시 넣는다. 개념 칸 밖(해설, 암기, 보기별 해설, 계산기 꿀팁)의 공식 줄 아래에 기호 뜻이 자동으로 붙는다. 문제에 나오는 모든 수학 기호를 표기 그대로 넣는다(d1과 D₁처럼 표기가 다르면 따로).
- `fig`(그림 id 배열)는 data/figures.js의 그림을 개념 칸 아래에 넣는다.
- `choiceNotes`는 "보기별 해설" 칸에 표시된다. 보기마다 term(용어 정의 1문장, 정오 판단 없이), theory(첫 문장에서 정오를 밝히고 이유 1~2문장, term·memo 반복 금지), practice(이 보기에만 해당하는 실무 장면·시험 함정 1문장, 다른 칸과 겹치면 빈 문자열 `""`로 두면 그 줄이 숨겨진다). 보기는 화면에서 섞이므로 "①", "1번" 같은 번호 참조는 금지하고 내용으로 부른다.
- OX와 4지선다를 섞되, 원문에 밑줄로 (ㅇ)/(x) 표시된 문장은 반드시 OX로 출제.
- 원문의 모든 소제목·표·숫자를 빠짐없이 커버. 표는 셀마다 문제화 가능.
- 숫자·비율·기간·주체(누가)는 고득점 포인트이므로 우선 출제.
- 원문 오타는 바로잡아 출제 (예: "배출액"→"매출액", "고졍비"→"고정비", "이상총수"→"이사총수").

## 계산 문제 (data/calc.js)

계산 문제는 `window.CALC_DATA.questions`에 모아 두고, 각 문항의 `area`(예: `"s3_bond"`) 영역에 앱 시작 시 합쳐진다. id는 `영역id_c2자리`(예: `s3_bond_c01`).
일반 문항 필드에 더해 `calc`를 넣는다.

```js
calc: {
  formula: "P = C/(1+y) + (C+F)/(1+y)²",           // 공식 한 줄
  steps: ["`500` `÷` `1.06` `=` `M+` → 471.70"],   // 계산기 키 순서. 백틱으로 감싼 부분은 키 모양으로 표시
  sci: "`500` `÷` `1.06` `+` ...",                   // 공학용(fx-570 계열) 키 순서 한 줄
  tip: "만기수익률 > 표면이자율이면 액면 미만..."      // 꿀팁 (백틱 사용 가능)
}
```

- `mockQuota`: 실전 모의고사에서 영역별로 계산 문제를 최소 몇 개 넣을지. 영역 문항 수보다 계산 문제가 적으면 있는 만큼만 들어간다.
- 공식을 추가하면 `data/formulas.js`에도 넣고, `qs`에 관련 계산 문제 id를 적는다.
- 숫자는 반드시 node로 재계산해 검산하고, 오답 보기는 "어떤 실수를 하면 나오는 값인지"가 분명한 숫자로 만든다.
